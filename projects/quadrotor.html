A connected autonomy pipeline

This project brought planning, control, and state estimation together in a quadrotor simulator. A route through free space is only the beginning: it has to become a time-parameterized reference that a controller can track using an estimated state.

  1. Represent free space

    Build a 3D occupancy grid with obstacle inflation for the robot’s clearance.

  2. Search and simplify

    Use A* for a dense route, then reduce it to sparse waypoints with shortcutting or Ramer–Douglas–Peucker simplification.

  3. Generate a reference

    Allocate segment times and generate the position, velocity, and higher derivatives required by the controller.

  4. Track and estimate

    Use SE(3) control to compute motor commands, with visual–inertial estimation providing pose and velocity information.

Planning and trajectories

The saved A* implementation searches a 26-connected voxel neighborhood. Edge costs are measured in physical distance rather than index distance; the heuristic is Euclidean distance to the goal voxel. The same search can run as Dijkstra by setting the heuristic to zero.

The trajectory code tries different clearance and nominal-speed settings, simplifies waypoints, and samples the resulting trajectory for collisions. Its polynomial mode uses piecewise fifth-order polynomials with endpoint position constraints, zero start/end velocity and acceleration, and continuity of velocity through snap at internal waypoints.

The same saved version also contains an RDP-based piecewise-linear reference mode. These are distinct construction modes; the code does not turn every simplified path into the same smooth polynomial trajectory.

Practical tradeoff. The code’s clearance margins, waypoint choices, and segment times affect both geometric feasibility and tracking difficulty. They were tuned for the course environments rather than presented as universal settings.

Source files: graph_search.py, occupancy_map.py, and world_traj.py.

From reference motion to motor speeds

The position loop combines desired acceleration, position error, velocity error, and gravity compensation to form a desired force. That force and the desired yaw define an attitude reference.

SE3_CONTROL.PY · DESIRED FORCEF_des = self.mass * (
    a_d
    + self.Kp * e_x
    + self.Kd * e_v
    + np.array([0, 0, self.g])
)

The attitude loop computes a rotation error and angular-velocity error. A rotor-mixing solve converts the thrust and moment command to individual rotor forces, then the implementation clips them to actuator limits and converts them to motor speeds.

Source file: se3_control.py. The excerpt is from the saved implementation, not a performance measurement.

Visual–inertial state estimation

The estimator propagates position, velocity, and attitude with bias-corrected inertial measurements. Its nominal state also carries accelerometer bias, gyroscope bias, and gravity; the accompanying error-state covariance is 18 × 18.

Image updates compare a projected landmark with its measured image position. Measurements with innovations above a threshold are rejected. Accepted measurements update the nominal state and covariance through the Kalman gain.

Source file: vio.py. The simulation script logs estimated and true state, trajectory tracking, actuator commands, and collision checks.

The local-replanning extension

A later extension added receding-horizon local replanning with finite-range occupancy updates, local goals selected from a guide path, and fallback behavior when a target was blocked or unreachable.

The code excerpts above cover the global-planning pipeline. The local-replanning extension adds finite-range map updates and repeated selection of a local target; it is a separate stage of the project.

The course work covered maze, window, stairwell, slalom, over-under, and switchback environments. I tuned the planner and controller together rather than assuming that geometric path clearance alone would ensure successful flight.

Course environments: maze, window, stairwell, slalom, over-under, and switchback. This project was evaluated in the course simulator.
